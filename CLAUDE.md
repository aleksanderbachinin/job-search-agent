# Job Search Agent

AI-агент, который круглосуточно работает в облаке и помогает Александру Бачинину искать работу. Он получает новые вакансии из сохранённых фильтров Hirify и для каждой подходящей готовит отклик: резюме под вакансию, сопроводительное письмо, ответы на вопросы формы и контакты нанимающих. Простые отклики агент отправляет сам, остальные отдаёт Александру на ручную отправку. По каждому отклику агент ведёт статистику и по ней корректирует свою работу.

Сейчас эту работу делает Claude Code по запросу, вручную. Результаты этой работы лежат в папке (см. «Что уже есть»). Задача проекта — превратить ручной процесс в автономный сервис.

## Кто пользователь

Александр Бачинин, Senior Product Manager, ищет продуктовую роль: удалёнка из России, удалёнка с переездом или офис с релокацией, лучше в русскоязычной компании.

Кто он, целевые роли, грейды, форматы и языки описаны в одном месте: [search_criteria.md](search_criteria.md), раздел «Критерии кандидата». Этот раздел читают все модели агента. Профиль меняется только там, здесь его не дублируй.

## Что агент делает

### 1. Приём вакансий
- **Источник:** сохранённые фильтры Hirify (ленты из [search_criteria.md](search_criteria.md), шаг 1). Telegram-канал больше не нужен.
- **Основной канал:** вебхук Hirify. На каждое новое совпадение Hirify присылает событие `vacancy.matched` с подписью HMAC-SHA256 (`X-Hirify-Signature` над `<timestamp>.<body>`). Сервис проверяет подпись, отбрасывает повторы по `X-Hirify-Delivery` и сразу отвечает 2xx.
- **Страховка:** два раза в день сервис читает первые страницы каждого фильтра (`feeds.vacancies`) и добирает пропущенное. Весь фильтр не листается: Hirify считает это копированием каталога.
- **Первый запуск:** текущее содержимое фильтров помечается как «уже было» и не оценивается. В работу идёт только новое.
- **Дедупликация:** по `slug` вакансии. Одна вакансия из нескольких фильтров обрабатывается один раз. Вакансии с `has_applied` или `in_tracker` пропускаются.
- Контракт API: `https://api.hirify.me/api/agent/openapi.json`, лимиты: `GET /api/agent/me`.

### 2. Разбор и оценка
Отсев в четыре ступени, от дешёвой к дорогой:
1. **Правила без LLM** по карточке: грейд, стоп-слова в названии.
2. **Быстрая модель (Haiku) по карточке:** подходит ли роль и направление. Полная вакансия ещё не открыта, лимит открытий не тратится.
3. **Полный текст (`vacancies.read`) и Haiku по нему**: свежесть по `created_at`, затем явные стоп-факторы из текста (офис без релокации, junior, не продуктовая роль). Отсекает около трети вакансий до LinkedIn-проверки и Sonnet.
4. **Sonnet:** оценка.

- Извлечение структуры: компания, роль, грейд, гео и формат, вилка, обязательные требования, канал отклика, контакт.
- **Скоринг 1–5:** обязательные требования, направление, условия, стоп-факторы, сигналы мошенничества. Вывод в три строки: два довода «за» и один «против» со ссылкой на текст вакансии, плюс что могло бы изменить оценку.
- **Проверка «русскоязычная компания»** с метками ✅ / 🟡 / ❓ / ❌ и доказательствами. Методика описана в [search_criteria.md](search_criteria.md), шаг 6.
- Вакансии ниже порога уходят в архив с причиной отказа. По этим причинам агент потом калибрует скоринг.

### 3. Подготовка отклика
Для каждой вакансии, прошедшей порог, агент собирает пакет:
- **Резюме под вакансию.** Markdown-исходник, затем PDF через общий генератор. Меняются заголовок, summary, порядок и формулировки буллетов, блок навыков. Факты не меняются. Имя файла: `Bachinin_Alexander_<Company>_<Role>.pdf`.
- **Сопроводительное письмо** строго по [cover_letter_guide.md](cover_letter_guide.md): до 300 слов, хук под компанию, кейсы STAR/CAR, без длинных и коротких тире, с чек-листом перед отправкой.
- **Ответы на вопросы формы** (ATS, Hirify, getmatch и т.п.).
- **`experience_map.md`:** сопоставление требований вакансии с опытом и честный список пробелов.
- **`APPLY.md`:** канал, ссылка, кому писать, что вставить в каждое поле, какие поля заполнить вручную (ожидания по ЗП, телефон и т.п.).

### 4. Контакты нанимающих (LinkedIn)
- Агент ищет hiring manager, рекрутера и руководителя направления в компании: имя, должность, ссылку на профиль, пост о найме, если он есть.
- Для каждого контакта готовит короткое сообщение для LinkedIn или Telegram.
- Контакты попадают в карточку вакансии, чтобы в момент отклика всё было под рукой.

### 5. Отправка
Каналы отклика (подробнее в [../applications_2026-10-01/README.md](../applications_2026-10-01/README.md)):
1. **Кнопка «Откликнуться» на Hirify** (`can_apply_directly`). Кандидат на автоотправку.
2. **Форма на сайте компании (ATS).** Автоотправка, только если форма простая и все поля закрываются фактами. Иначе ручная отправка.
3. **Личный контакт** (Telegram, email, LinkedIn). Всегда вручную: агент готовит текст, Александр отправляет сам.

Политика автоотправки:
- Автоотправка выключена по умолчанию. Включается отдельно для каждого канала по белому списку.
- Ничего не уходит работодателю без одобрения Александра: подтверждения карточки в Telegram-боте или заранее заданного правила.
- В автоматическом режиме агент никогда не придумывает ответы на поля с личными данными (ЗП, телефон, гражданство, дата выхода). Такие отклики уходят в ручную очередь.
- Если форма содержит анти-LLM-ловушку или вопросы «своими словами», отклик уходит в ручную очередь.

### 6. Интерфейс для Александра
- **Telegram-бот.** Карточка вакансии: скор, RU-метка, ключевые требования, пробелы, файлы, контакты. Кнопки: «Отправить», «Отправлю сам», «Пропустить», «Переделать».
- После ручной отправки Александр отмечает статус в боте. Ответы работодателей тоже фиксируются: сообщение в боте или, позже, автоматически из почты.
- Ежедневная сводка и еженедельный отчёт со статистикой.

### 7. Статистика и самообучение
- **Воронка по каждому отклику:** найдено → прошло скоринг → подготовлено → отправлено → ответ → интервью → оффер / отказ.
- **Срезы:** канал отклика, источник вакансии, тип роли, версия резюме, версия промпта, наличие сопроводительного и прямого контакта, RU-метка, гео.
- **Что агент корректирует сам:**
  - пороги и веса скоринга по фактическим ответам работодателей;
  - выбор базовой версии резюме и порядок кейсов под тип роли;
  - формулировки хуков и сообщений: A/B-варианты с подсчётом конверсии в ответ.
- **Изменения промптов и правил версионируются.** Агент предлагает изменение с обоснованием из статистики, Александр подтверждает. Тихо переписывать свои инструкции агенту нельзя.
- Отказы Александра («пропустить», «переделать») с причиной — тоже обучающий сигнал.

## Жёсткие правила

1. **Только реальные факты.** Все цифры, названия компаний, инструменты и достижения берутся из файла опыта `experience/Bachinin_Alexander_Experience.md` и подтверждённых источников (см. «Источник фактов»). Утверждение без источника удаляется или помечается «уточнить». Прецедент из прошлых генераций: агент выдумал «Wildberries/Ozon market intelligence» и «low-code tools».
2. **Без одобрения ничего не отправляется:** ни отклик, ни раскрытие контакта на Hirify, ни сообщение.
3. **Сопроводительные пишутся по гайду.** Без тире, без шаблонных фраз, до 300 слов.
4. **Пробелы показываются честно.** Если обязательного требования нет в опыте, агент пишет об этом в `experience_map.md` и не маскирует пробел формулировками.
5. **Персональные данные** (контакты, ЗП, переписка) хранятся только в приватном хранилище. В логи и сторонние сервисы они не уходят.
6. **Лимиты площадок.** Агент соблюдает rate limits и правила Hirify, LinkedIn и ATS. Он не обходит капчи и антибот-защиту.

## Архитектура

```
Hirify (вебхук vacancy.matched + страховочный опрос фильтров)
        │
        ▼
     Ingest ─► Очередь ─► Правила ─► Haiku по карточке ─► Haiku по тексту ─► Sonnet
                                              │
                                              ▼
                              Research (RU-проверка, LinkedIn)
                                              │
                                              ▼
                                   Generate (CV, письмо, ответы)
                                              │
                                              ▼
                     Telegram-бот (одобрение) ─► Apply (авто / ручная очередь)
                                              │
                                              ▼
                             Tracker + Analytics ─► Feedback loop (скоринг, промпты)
```

Стек:
- **Сервис:** один Python-процесс в [agent/](agent/): FastAPI принимает вебхуки Hirify, aiogram ведёт Telegram-бота (long polling, публичный адрес боту не нужен), фоновый воркер разбирает очередь. Запуск и настройка описаны в [agent/README.md](agent/README.md).
- **LLM:** Claude API (Anthropic SDK). Haiku для грубого отсева по карточке и по полному тексту, Sonnet для оценки, Opus для генерации текстов. Цепочка шагов фиксирована в коде. Агентный цикл с инструментами нужен только там, где требуется поиск в интернете (RU-проверка, LinkedIn).
- **Источники:** Hirify Agent REST API (`https://api.hirify.me/api/agent`, ключ из кабинета hirify.me/mcp-api), позже LinkedIn через сторонний API, без автоматизации личного аккаунта.
- **Хранилище:** SQLite на старте (вакансии, события воронки, доставки вебхуков), позже Postgres. Объектное хранилище для PDF.
- **Выполнение 24/7:** VPS Александра в Таллине (systemd + Caddy, HTTPS через `193-42-112-144.sslip.io`). На том же сервере его VPN: Shadowsocks, Xray, WireGuard, dante и файрвол без его согласия не трогать. Выкладка только из git-коммита через `./deploy.sh` (тесты → копирование → перезапуск → `/healthz` с номером коммита → журнал без ошибок), откат `./deploy.sh prod`. Подробности в [agent/README.md](agent/README.md), раздел «Рабочий сервер». Сервер должен быть вне России: оттуда Claude API недоступен.
- **Генерация PDF:** генератор на reportlab перенесён в сервис, модуль `agent/jobagent/pdf.py`: фиксированные стили, ровно одна страница A4, при нехватке места сокращается содержание.
- **Наблюдаемость:** логи каждого шага, стоимость LLM-вызовов на вакансию, алерты в Telegram при сбоях.

## Этапы

1. **MVP-1: отбор (работает).** Вебхук и опрос Hirify → правила → Haiku → Haiku по тексту → Sonnet → карточка в боте с оценкой, RU-меткой и выводом. Кнопки «Откликнулся» (запись в трекер Hirify) и «Пропустить» с причиной (скрытие в Hirify). Простая `/stats`.
2. **MVP-2: пакет отклика (работает).** Кнопка «📝 Подготовить отклик»: резюме под вакансию с проверкой каждого утверждения по номерам фактов, PDF на одну страницу, сопроводительное по гайду, `experience_map.md`. Кнопка «Переделать». Кнопка появляется, когда на сервере заданы `CANDIDATE_EMAIL` и `CANDIDATE_LINKEDIN`.
3. **Трекер и статистика:** статусы до интервью и оффера, синхронизация с `applications.list`, ежедневная сводка и еженедельный отчёт.
4. **Контакты:** поиск нанимающих в LinkedIn, готовые сообщения.
5. **Автоотправка:** Hirify direct apply с подтверждением в боте, затем простые ATS-формы по белому списку.
6. **Самообучение:** калибровка скоринга, A/B текстов, предложения по изменению промптов.

## Открытые вопросы

- Какой сервис брать для поиска людей в LinkedIn, и какой бюджет на него?
- Порог скоринга для подготовки пакета и лимит пакетов в день. Сейчас в боте показываются вакансии с оценкой от 3.
- Месячный бюджет на LLM. Оценка одной вакансии Sonnet стоит около 2 центов (оценка 2026-10-28, после перехода на часовой кеш; до этого около 3,8 цента, из них 2,6 — повторная запись кеша). Проверить по `cache_write_tokens` в событиях `llm` через несколько дней.
- Из Таллина `api.hirify.me` часто отвечает 503: DNS отдаёт сбоящий сервер Hirify (176.124.211.64), второй (46.4.59.233) работает. Клиент повторяет запросы. Александр решил (2026-10-26) в Hirify не писать и работать с повторами.
- Как фиксировать ответы работодателей: вручную в боте, через почту (Gmail API) или через Hirify `applications.list`.
- Тариф Hirify Plus действует до 2026-11-02. Нужно проверить, сохранится ли доступ к Agent API после окончания тарифа.

## Как вести разработку

Скиллы Superpowers лежат в `../.claude/skills/`. Порядок для этого репозитория:

- **Версии.** Папка — git-репозиторий, копия на GitHub `aleksanderbachinin/job-search-agent` (приватная). Правку кода, промпта или критериев коммить отдельно с понятным сообщением: история коммитов и есть версии промптов и правил. Что изменилось с выкладки: `git diff prod`.
- **Код** (правила, скоринг, бот, приём): сначала падающий тест, потом код (test-driven-development). Перед коммитом полный `cd agent && uv run pytest -q`.
- **Промпты** (`scoring.py`, `search_criteria.md`, файл опыта, `applied_examples.md`): прогон `uv run python -m jobagent.cli eval <шаг>` до правки и после, сравнение через `--compare`. Ложный отсев вакансии с оценкой 4–5 блокирует правку. Цифры до и после идут в сообщение коммита.
- **Сбои на сервере:** сначала причина по журналу и `dry-run`, потом правка (systematic-debugging). Догадки без воспроизведения не выкладываются.
- **Перед выкладкой:** ревью `git diff prod` отдельным субагентом (requesting-code-review). Критичные и важные замечания исправлены.
- **Выкладка** только через `./deploy.sh`. «Выложено» пиши, только когда скрипт напечатал «✓ Выложен».
- История изменений — в [CHANGELOG.md](CHANGELOG.md), в этом файле и в HOW_IT_WORKS.md даты «с такого-то числа» не пишутся.
